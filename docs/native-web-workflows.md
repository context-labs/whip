# Native web workflow inventory

Current protocol-v4 shared-renderer classification. The [native generated manifest](../packages/protocol/schema/manifest.json) is the complete operation authority; this document describes current consumers, not a second protocol registry. It replaces the executable test's dependency on the historical v3 inventory.

- **Web**: a concrete shared-renderer workflow consumes this operation, directly or through a native SDK service/view. Desktop-only native Browser controls are called out explicitly.
- **Internal**: transport, peer replies, observation or exact-receipt machinery supports a workflow; it is not a separate user action.
- **SDK-only**: the native typed API is available, but no current shared-renderer control invokes this operation. Some have CLI/TUI consumers. This classification neither retires a retained requirement nor claims parity for a missing UI.

Every row names an actual source owner. A source link establishes implementation scope, not proof that every operating system, account or browser acceptance case passed. Current validation and outstanding work remain in the [redesign plan](backend-redesign-plan.md) and [development record](backend-redesign-development.md). Mobile has its own renderer and is not inferred from the Web column.

The [inventory test](../packages/app/test/workflow-inventory.test.ts) requires exactly one classification for every native operation and checks local source links. Updating the protocol requires reviewing this document; historical plans remain historical evidence.

## Ownership and limits

The shared renderer consumes SDK SessionView, ExecutionView, TraceView and tree catalog views rather than maintaining a second execution cache. Native decimal counters retain exact string/BigInt semantics; cursor opacity and runtime/root/session/epoch scopes are preserved. Host configuration revisions and immutable definition references are not inferred from local drafts.

Submission, policy edits, reload, root creation and other durable commands keep their exact request identity. Disconnect stops observation; it does not cancel daemon work. Reconnect never automatically resends an uncertain mutation. Terminal and native Browser peers have separate process/generation-bound lifetimes and cannot restore authority from saved tab metadata.

Recorded tool execution, schema display and scoped content preview are observation, not a manual execution console. Likewise read-only budget/resource presentation is not a limit editor; a native API method's existence alone does not establish a renderer control. The SDK-only rows deliberately expose these boundaries for parity review.

This operation inventory does not enumerate every backend capability behind tool.call or a browser provider. In particular, native Browser tabs/provider peers do not by themselves prove support for every Chrome driver mode, installed native helper, OS permission or real account. Those families require their own implementation and acceptance evidence.
