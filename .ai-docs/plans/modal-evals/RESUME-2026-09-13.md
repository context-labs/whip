## Risks at 90 attempts, and why they are bounded

- **Export validation vs the 600 s worker wait.** The controller re-hashes every exported file through the Volume API before acknowledging; HTTPX's 5,190 files took longer than the worker's 600 s wait, which is exactly the late-ACK race. Validation runs inside each trial's own thread (`run_pool` with `jobs` workers in `coordinate`), so it is serial per attempt, not across the campaign. With the fix, a worker that times out simply exits and the controller records `obsolete_actual_exit`; the cost is up to 600 s of idle VM per large repository attempt, about $0.24 each, at most ~$7 across the 27 Pier attempts. A worker-side manifest hash would remove the wait entirely; that is a follow-up, not a prerequisite.
- **Coordinator lifetime.** The Modal function runs with `timeout=86400`, one claim per run, cancel watched every 2 s; a coordinator death leaves evidence on the Volume for `reconcile` and `fetch`.
- **Fetch time.** REAL2 fetched 5,242 files in about six minutes with the 8-stream collector; the reviewer estimated 35 to 45 minutes for 90 attempts. Disk on the box has room.
- **Provider capacity.** 90 concurrent Kimi K3 streams was declared "arranged" by Sam and never tested above 2. Admission and provider errors surface in `status` within minutes; the stop rule in question 2 covers it.
- **Cleanup proof.** `cleanup_complete` means an observed integer VM exit, never a termination acknowledgement; `modal container list --env whipcode` after the run must be empty, and any stragglers are terminated by hand and recorded.

## Platform gotchas recorded by the failed session

Modal SDK 1.5.5 on this box: always pass `--env whipcode` (default is `main`); run host commands with `env -u INFERENCE_API_KEY` because the literal key sits in the interactive shell profile and must never reach a host process, log, or bundle; `Volume` has no hard links, so native receipts stay on VM-local ext4 and are copied once; `/evidence` is a symlink to the mounted Volume; `reload_volumes()` is unsupported in VMs, so inputs must be committed before VM creation; `sandbox.terminate()` returns on RPC acknowledgement, not exit, and `NotFoundError` is never proof of exit; exec handles vanish after VM shutdown; host Python is 3.14 while the controller image is 3.12, so nothing may be pickled across; the campaign jobs cap is 90 (`MAX_JOBS`). Task-level failure modes seen natively and expected again: 300 s dependency-bootstrap timeouts and 600 s `context deadline exceeded` on long reasoning; both are recorded, not retried.
