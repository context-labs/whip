# Loading-state audit, 2026-09-13

Live app: `http://127.0.0.1:4000` (web build, Local host only, dark theme), Chromium
Browser pane at 800×868 CSS px. Layout shifts were captured with
`PerformanceObserver({ type: 'layout-shift' })` (rects below are in the observer's
device-pixel space, ~1.43× CSS px). Every flow was also screenshotted at 0 ms,
~300 ms and ~1.5 s after the click.

No remote host was configured in this environment, so remote timings are inferred
from the code: every state below that lasted 50–75 ms on Local lasts one host
round trip (typically 0.5–3 s over SSH) on a remote host.

## 1. Cold reload of a session URL

- Buffered observer after a full reload: **0 layout-shift entries**.
- The startup splash (`packages/app/src/startup-screen.tsx`) keeps the app
  `visibility: hidden` and `inert` until the Local connection settles (or 3 s).
  Everything below loads under the splash on a fast local host, so the cold path
  is clean here. Loading states become visible only when a host answers slower
  than the splash, or on any client-side navigation.

- line 266–278: `cwd={… root?.meta.cwd …}` → `SessionInfoBar` substitutes

  `unavailableReason={connected && !root ? 'Session content is unavailable.' : undefined}`;
  `modelControl={root && <>…</>}`.

The SDK sets `status: 'live'`, `root` and the first history page in one snapshot
(`packages/sdk/src/state.ts:314-323`), so there is no separate “root but no
history” frame; the empty-conversation copy is not a loading flash.

## 3. New Chat (sidebar “New session”)

Two entries. The relevant one at `t = 50 ms`, value 0.0053:

| Node | Before | After |
|---|---|---|
| welcome column `DIV` | y 555, h 130 | y 495, h 250 |

The column is vertically centered (`marginBlock: 'auto'`), so it grew 120 px and
re-centered 60 px upward. Cause (`packages/app/src/welcome.tsx`):
- line 108: `ready` is false until `providers.inventory` resolves.
- line 147–148: `setupVisible = (!ready || showProviders) && …`, so the first
  paint is the heading **“Connect a provider to get started”** plus
  `ProviderSetup` (“Checking providers on Local…”, `provider-setup.tsx:69`), then
  the composer replaces it.
- line 66–70: for a host without `connection.info` yet, `NewSession` renders
  heading + “Connecting to {host}…” text and no composer at all; the composer
  appears when the handshake completes (same re-centering jump, longer on
  remote hosts).
- line 159–163: while not ready the model slot is a **“Connect a provider”**
  button, another wrong state during a normal load.

The other entry (value 0.0001) is the tab strip making room for the new tab;
expected.

## 6. Reviewed in code, no shift expected

- Tab strip status icon: `CircleHelp` → `MessageSquare`/dot, all 13–14 px in the
  same slot (`session-tab-strip.tsx:24-29`).
- Sidebar row indicator: fixed 12 px slot; dot (5 px) and spinner (10 px) swap
  inside it (`session-sidebar.stylex.ts` `indicator`).
- Reading list: “Load earlier messages” keeps its measured space via
  `visibility: hidden` when exhausted (`reading-list.tsx:16, 295`).
- Remote directory dialog: `keepPreviousData`, row-sized placeholders and a 180 ms
  delayed indicator (`remote-directory-dialog.tsx:86-101`); SSH profile list uses
  three `Skeleton` rows behind a status line (`connection-dialog.tsx:53`). These
  are the existing house patterns.
- Settings: `ConfigurationSettings` keeps the previous config while refetching
  (`settings/configuration.tsx:51-53`); the bare “Loading providers…” /
  “Loading agents…” / “Loading host defaults…” lines disappear when data lands,
  shifting the section below by one text line. Host-bound sections only.
- Tab titles: tabs restored from storage or opened from a URL start with
  `titleHint: ''` (`session-tabs.ts:483`) → “Untitled session” until the first
  summaries poll or the root snapshot supplies the title; the tab is
  content-sized so its neighbours move once. Sidebar/search/attention opens pass
  the title (`tabs.open(…, title)`), so this only affects deep links.

## After the change (same day, working tree)

Harness: the working-tree app served by a scratch Vite config in the session
scratchpad on port 3100, proxying `/api` to the onboarding container's daemon
on port 4000 with the Origin header rewritten to `http://127.0.0.1:4000` (its
allowlist returns 403 for other origins). No repo file and no daemon changed.

any appearance of “Directory unavailable”, “Session content is unavailable”,
“Connect a provider”, “not available”, “Checking providers”, “Reconnecting”,
“Session unavailable” in `document.body.innerText`.

Two intermediate observations worth keeping:
- On the first pass the info bar still filled the project in one round trip
  late (`Local` → `Local / whip`, value 0.0009) because the tab-strip summary
  for a just-opened tab has not been fetched. The sidebar's catalog already
  holds the session's `cwd`, so the strip now falls back to it (`knownCwd`).
- Vite re-optimized dependencies once during the run and reloaded the page,
  which interrupted the first Settings measurement; it was repeated cleanly.
