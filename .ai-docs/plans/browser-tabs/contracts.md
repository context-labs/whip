# Browser tabs v1 integration contracts

Status: root-approved implementation contracts, 2026-09-17. This freezes interfaces/policy so independent lanes can implement; it does **not** mark Phase 0 or any acceptance gate complete. The implementation ledger owns test status. Plan proposals yield to these recorded decisions.

## Ownership

- `browser-native`: new `packages/app/src/browser-types.ts` (human browser types), serialized browser part of `desktop-bridge.ts`, desktop adapter implementation in `apps/web/src/platform/desktop.ts`, Electron manager/security/CDP, `main.ts`/`preload.ts`, native tests. Publish type file first and coordinate changes directly with workspace/root.
- `browser-workspace`: `platform.ts` optional browser property importing those types; SessionTabs, workspace/routes and route generation; all app Browser UI, commands, settings navigation and generic UI overlay/focus integration; corresponding tests. Do not edit canonical docs or provider/permission logic owned by root.
- `browser-agent`: Go capability/permission, browser adapter/helpers, RLM bindings/definitions, daemon broker, protocol registry/types and its generated schemas/validators, MCP handler integration and Go tests. Sole protocol generation owner; notify root before generation. Do not edit SDK/app/native files.
- `browser-ssh`: preview proxy/environment owner + focused native SSH route additions/tests in `ssh.ts`; no main/preload edits. Coordinate native manager constructor integration with native owner. Remote tests use only a confirmed host and owned temporary resources.
- Root: SDK browser provider transport/service and request-card resource display; cross-lane wiring, canonical docs, audits, acceptance and commits. SDK `browser.ts` reserved for root. As of 15:01 UTC, workspace lane also owns app provider registration/selection/coordinator and its tests; native lane owns the requested complete daemon→SDK→preload integration fixture after the selected-host gate.

## Human workspace/native contract

1. Browser descriptor `{id, kind:'browser', url, titleHint, environmentId?}`. Environment is an opaque native-owned restore hint, never route/control authority. No runtime/root/agent/native profile/debugger/grant fields in persistence.
2. Keep the existing v3 tree/storage envelope: this is an additive kind, not a new layout. Parse/preserve it on browser-less clients. No v4 migration needed; explicitly document older binary downgrade limitations and preserve a pre-browser backup before first Browser persistence so old parsers cannot irreversibly erase addresses. Existing v1/v2 restoration remains tested.
3. Root approved ceilings: refuse NEW Browser creation beyond 8 Browser descriptors within existing 32 total; at most 8 live guests and 4 presented. Restore must retain up to 32 otherwise-valid Browser metadata descriptors rather than destructively dropping over-cap pages; excess stays visibly unavailable until capacity is freed, never evicts a form. URL 8192 UTF-8 bytes; title existing 128-codepoint cap; 64 KiB total layout metadata. One native page per realized descriptor; split/move preserve it, Duplicate/Reopen get new IDs and no grants.
4. Optional `AppPlatform.browser` wraps a narrow optional version-1 `DesktopBridge.browser`. Adopt native/workspace agreed BrowserPlatform v1: `snapshot`, metadata-only `restore`, `create`, idempotent `admitted`, `present`, `act` with a CLOSED discriminated BrowserAction union, `close` with closed/cancelled acknowledgment, and `onEvent`. Snapshot is `{epoch,revision,tabs}`; target mutations quote `{epoch,tabId,generation}`; status restored/ready/unavailable/crashed; restore inserts metadata only and never overwrites a live committed URL. Actions include navigation/history/focus/find/zoom/guest-DevTools/profile clear, never generic arbitrary methods or JS. Exact shared types are owned by native and published first to workspace/root; the adapter may provide cached observation helpers.
5. Presentation is `present({epoch,revision,slots:[{tabId,slotId,bounds:{x,y,width,height}}],blocked}):Promise<void>`. Full bounded snapshot, native-issued renderer epoch, monotonic safe-integer revision, CSS viewport coordinates below toolbar. Main validates sender/window/epoch/IDs and maps trusted app zoom to DIPs; never DPR. ACK means applied. Hide immediately on renderer loss.
6. Generic UI overlay holds are balanced owner tokens. Native hide ACK gates overlay mounting/interactivity, including default-open controlled overlays; an after-render effect is insufficient. Release after close animation/focus restoration and remeasure before showing. Include direct comboboxes, tooltips, toasts and DnD portals. If coverage proves unsafe, keep native pages hidden rather than weaken the permission boundary.
7. Main publishes state before returning native creation. A model-created tab requires bounded renderer admission ACK into the bound originating pane/window before model success. No focus stealing; open agent pages in background by default. Capacity/admission failure removes unowned native resources. Beforeunload cancellation preserves descriptor/page. Unavailable bridge can close its inert descriptor without claiming native destruction.
8. Page state snapshot includes epoch, tab/instance/event/document IDs, committed URL/title, navigation/loading/error state, network provenance and controller observation. Cache is observation only. Separate focus/shortcut events update pane selection using fixed app-command allowlist, never arbitrary shortcuts/code.

## Agent operations and provider protocol

Adopt the exact structured `BrowserScope`, `BrowserPreviewScope`, `BrowserCall`, result envelope, and provider/command wire proposal in `evidence-agent.md` §§Frozen-shape proposal/Wire, with the constraints here.

- Model methods: open(url, preview_host_id?), attach(tab_id), run(attachment_id, code, expected_document?, timeout?), allow_preview_port(attachment_id, port), detach(attachment_id). Legacy run(session,code) behavior remains unchanged; mutually exclusive targets; no fallback.
- Browser capability allows asking; resource-specific grant is separate. Resolve canonical offered scope in Services before existing dispatcher admission/payload digest, following MCP resolution. New Browser field in existing grant/scopes serialization; no competing permission DB, generic dispatcher hook, signer/enrollment, or filesystem-scope encoding.
- Open/attach/port expansion reuse existing durable permission requests and revalidation. **Once only** for these operations in v1; no remembered/wildcard browser rules until exact matcher tests justify a later increment. Automatic mode stays within explicit user-offered desktop/resources and native hard restrictions.
- Explicit delegation: add optional `browser_attachments:[attachment_id]` to existing `agents.spawn` in both engines. Validate parent ownership/live scope and child's narrowed browser capability; copying IDs outside this argument conveys no authority. A successful spawn transfers each selected controller to a new child-bound handle/grant with ancestor ID+generation, cancels the parent's pending work, and leaves the ancestor authorization row delegation-only (no executable control) so ancestry remains valid. Parent detach/stop/revoke cascades through delegated handles. Bound count by browser cap; reject duplicates, widening and partial handoffs. Do not start child work before native handoff acknowledgment; failed spawn/handoff must revoke/clean up tentative child grants and leave an explicit outcome rather than orphan control. Parent's old handle remains usable to revoke its delegation, not to act on the child page. Child context/inspection receives its own bounded attachment metadata. Also permit fresh user-approved attach/handoff to a child. No implicit attachment inheritance.
- `browser.provider.bind` is an explicit user-selected root-to-desktop/window association on the authenticated holder connection. A mere initialize flag/first client/focused page is not selection. Second provider cannot steal; replacement requires expected current epoch and user action. Willingness can be advertised, authority cannot.
- Explicit `browser.provider.unbind({root_id,provider_epoch})` is exact-holder/epoch and idempotent only for that holder's previously released epoch, never a replacement. Independent `browser.provider.revoked{root_id,provider_id,provider_epoch,reason}` tears down idle native control as well as active work. SDK transport loss releases native authority independently, and reconnect never reselects. Human tabs are not closed by provider release. Historical roots without the new `browser.*` module grants remain fail-closed; v1 requires a fresh root rather than silently broadening stored authority.
- Reuse serverConn/executor **patterns**, not executor.bind's definition-wide newest-wins lease. Commands/results/cancel/events only match pointer-identical holder, root, provider epoch, attachment generation and unique per-CDP command ID. Inert IDs can be allocated before consent; no page/tunnel/network creation before approval.
- Serialize the whole run batch per tab: 1 active + 4 queued. Cancellation/revocation blocks subsequent commands; uncertain delivered mutations are never replayed. Execute timeout 60 s default / 120 s maximum excludes permission wait. Document tokens are opaque strings; validate before action and across competing user navigation.
- CDP transport is an injected Rod CDPClient over existing daemon/client channel, not a production WS debug port. Fixture-only restricted WS is acceptable native proof. Main default-denies exact method/parameter escape surfaces, other targets, app renderer, profile-wide credentials and filesystem APIs. Initial agent file upload/download helpers explicitly unsupported pending authorized byte transfer; human file inputs/downloads are separate.
- Screenshot/content payloads use existing authorized upload/chunk/finish/content facilities on selected connection, bounded bytes/digest/root/agent. No multi-MiB event frames or shared-filesystem assumptions. Structured routine errors are values; preserve legacy helper output/screenshot sink.
- Native provider admission/dispatch methods are a separate typed trusted-app bridge from human toolbar methods. Bind native to selected root/provider/connection epoch; check on every command. App/SDK forwards admitted operations only. Expose no generic Electron invocation.
- Standalone MCP tool host remains deny_permissions by default. Whip browser handlers reuse gates and fail clearly while unpaired/ungranted; no silent visible-conversation borrowing and no third-party Playwright adapter required to ship.

## SSH environment contract

- Only SSH: local Mac page engine, website route on approved SSH master. URL/Tailscale transport excluded.
- Native environment identity: offered saved host ID + verified remote daemon/runtime identity + fresh existing SSH master generation + stable project identity. Do **not** claim runtime ID is an SSH key fingerprint. Preserve existing known_hosts verification; identity/config changes require renewed approval.
- Persistent isolated environment partition, fixed private authenticated HTTP proxy; explicit `<-loopback>` bypass subtraction, no DIRECT fallback. Proxy pins literal approved remote loopback destinations; public paths are validated/resolved without private/rebinding escape. Disable non-proxied UDP/WebRTC and QUIC; test unsupported transports fail closed. No weakening CORS/CSP/TLS.
- SSH route method: `acquirePreviewRoute({remoteHost:'127.0.0.1'|'::1',port,expectedGeneration}, signal)` returning generation + bounded cancellable `open(signal):Promise<Socket>` + idempotent close. Only existing master `-O forward/cancel`, private socket endpoints, no new connection fallback. Revoke/disconnect closes live streams as well as future access.
- Session-wide routes imply environment-wide port policy. An expansion must not silently broaden another controller: invalidate incompatible attachments or isolate an environment, and require explicit scope refresh before commands resume. A model detach does not tear down separately approved tab-lifetime human routes.
- Native keeps secrets/profile names/socket paths out of renderer/model/logs. Exact proxy challenge verification includes session/WC/proxy endpoint/realm; no leakage to website challenges.

## Phase/release discipline

Proof completion and implementation authorization are distinct. Independent proven seams may proceed, but unresolved native transport/compositor/connected-SSH proofs remain explicit gates in Phase 0 and final acceptance. Tests run against production preload/SDK/IPC in integration, not only a fixture. Actual remote-host, signed/packaged artifact and physical/manual accessibility coverage must never be inferred from mocks or skipped tests. Feature flag remains off for broad release until acceptance is truthful.
